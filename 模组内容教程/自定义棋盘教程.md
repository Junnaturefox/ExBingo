# 自定义棋盘教程

本文面向会编辑整合包配置文件的玩家或服主，说明如何用一份 tierlist 制作只抽取指定内容的 ExBingo 自定义棋盘。

> **当前版本的棋盘现状**
>
> ExBingo 现在只内置 4 个原版棋盘（`items`、`in_overworld`、`advancements`、`simplified`），过去随模组附带的模组棋盘已全部移除。所以：装了其他模组后，它的物品/进度默认不进棋盘，**按本文做一份自定义棋盘就是不引入第三方数据的唯一精确做法**（另一种是按命名空间用 `+from=<模组id>` 粗粒度引入，见文末对比）。
>
> 做完本文的步骤后，记得 `/reload` 或重启（棋盘列表有缓存），并用 `/bingo carddisable list` 确认新棋盘没有被关闭。

自定义棋盘由两部分组成：

- 难度表：写入棋盘可抽取的目标，以及它们所属的 S/A/B/C/D 档位。
- 棋盘筛选：把这份难度表显示到游戏内的棋盘筛选列表中。

示例使用的棋盘名为 `enigmaticlegacyplus`。棋盘名来自文件名，不需要和模组 ID 完全一致，但配置中的名字必须和 tierlist 文件名一致。

## 难度表文件

将难度表放入：

```text
config/exbingo/tierlists/enigmaticlegacyplus.tierlist.json
```

文件内容：

```json
{
  "replace": false,
  "values": [],
  "S": [
    "item!enigmaticlegacyplus:dragon_breath_bow"
  ],
  "A": [],
  "B": [],
  "C": [],
  "D": [],
  "groups": []
}
```

这份文件表示：名为 `enigmaticlegacyplus` 的棋盘目前只包含一个 S 档物品目标 `enigmaticlegacyplus:dragon_breath_bow`。若要生成正常可玩的完整棋盘，需要继续向 S、A、B、C、D 中补充足够数量的目标。

## 字段说明

`replace`：控制同名 tierlist 合并时是否整份替换前面的内容。玩家手写自定义棋盘通常保持 `false`。不要把它当作“是否替换棋盘筛选”来使用；设为 `true` 可能导致同名来源的已有内容被整份覆盖。

`values`：未指定固定难度的目标。这里的目标会作为通用候选参与抽取。普通自定义棋盘建议优先把目标写入 S/A/B/C/D，保持 `values` 为空。

`S`：最高难度目标。适合终局物品、稀有掉落、Boss 核心掉落、长流程收集目标。

`A`：高难度目标。适合中后期装备、较难结构或维度内容、需要明显前置流程的目标。

`B`：中等难度目标。适合有一定流程或材料成本，但不属于终局内容的目标。

`C`：较低难度目标。适合早期合成、基础设备、常见探索内容。

`D`：最低难度目标。适合开局或很容易获得的内容。

`groups`：同类目标分组。适合颜色变体、材质变体、同系列方块等内容。放入同一组后，同组成员的抽取权重会被分摊，降低同类变体在棋盘上大量重复出现的概率。

示例：

```json
"groups": [
  [
    "examplemod:red_gem",
    "examplemod:blue_gem",
    "examplemod:green_gem"
  ]
]
```

## 目标类型限制

目标可以直接写资源 ID：

```json
"enigmaticlegacyplus:dragon_breath_bow"
```

没有类型前缀时，ExBingo 会按默认顺序查找可用目标。多数物品目标可以这样写。

当物品 ID 和成就 ID 相同，或玩家希望明确指定目标类型时，可以加类型前缀：

```json
"item!enigmaticlegacyplus:dragon_breath_bow"
```

```json
"advancement!enigmaticlegacyplus:dragon_breath_bow"
```

`item!` 表示只按物品目标处理。`advancement!` 表示只按成就目标处理。前缀只用于限制目标类型，后面的资源 ID 仍然保持原本的 `命名空间:路径` 格式。

同一个资源 ID 如果同时存在物品和成就，可以分别写入不同档位：

```json
{
  "S": [
    "advancement!examplemod:same_id"
  ],
  "A": [
    "item!examplemod:same_id"
  ]
}
```

棋盘生成时会按前缀查找对应类型，避免把成就误当成物品，或把物品误当成成就。

## 棋盘筛选配置

打开：

```text
config/exbingo/config.json
```

在已有的 `itemFilterPresets` 中追加棋盘名：

```json
{
  "itemFilterPresets": {
    "everything": "-tedious -unobtainable",
    "enigmaticlegacyplus": "+enigmaticlegacyplus"
  }
}
```

`"enigmaticlegacyplus": "+enigmaticlegacyplus"` 的含义是：新增一个名为 `enigmaticlegacyplus` 的棋盘筛选，并让它只引用 `enigmaticlegacyplus.tierlist.json` 中写入的目标。

如果 `config.json` 中已经存在 `itemFilterPresets`，只追加新的一行，不要新建第二个 `itemFilterPresets`。JSON 需要保持合法格式，最后一项末尾不要加多余逗号。

## 筛选名对应关系

文件名和筛选值需要保持一致：

```text
config/exbingo/tierlists/enigmaticlegacyplus.tierlist.json
```

对应：

```json
"enigmaticlegacyplus": "+enigmaticlegacyplus"
```

换成其它棋盘名时也按同一规则填写。例如文件名是 `my_board.tierlist.json`，配置中就写 `"my_board": "+my_board"`。

## 棋盘名称显示

游戏内棋盘筛选列表显示的是翻译键：

```text
bingo.list.<棋盘名>
```

示例棋盘名是 `enigmaticlegacyplus`，对应的翻译键就是：

```text
bingo.list.enigmaticlegacyplus
```

没有汉化时，游戏会显示默认格式化后的名称。需要显示中文名称时，可以用资源包添加语言文件：

```text
assets/exbingo/lang/zh_cn.json
```

写入：

```json
{
  "bingo.list.enigmaticlegacyplus": "神秘遗物+"
}
```

资源包加载后，棋盘筛选列表中的 `enigmaticlegacyplus` 会显示为 `神秘遗物+`。

同一规则也适用于其它自定义棋盘。例如棋盘名是 `my_board`，汉化键就是：

```json
{
  "bingo.list.my_board": "我的自定义棋盘"
}
```

## 与模组来源筛选的区别

`+enigmaticlegacyplus` 引用指定的 tierlist 文件，只抽取该文件中写入的目标。

`+from=enigmaticlegacyplus` 按模组命名空间筛选，范围更宽，可能包含该模组下其它已分类内容。用它的推荐写法是同时排除未分类内容，避免大量未经平衡的东西混进棋盘：

```text
/bingo filter +from=enigmaticlegacyplus -uncategorized -unobtainable -unbreakable
```

玩家制作“只包含自己写入内容”的自定义棋盘时，推荐使用 `+棋盘名`，不要使用 `+from=模组ID`。

## 棋盘预设有两个来源

棋盘筛选（preset）会从两处合并：

1. 数据包/内置：`data/exbingo/exbingo/filters.json`（模组自带的 4 个原版棋盘就在这里）。
2. 配置文件：`config/exbingo/config.json` 的 `itemFilterPresets`（本文使用的方式）。

**同名时以数据包为准**，所以你无法用 `itemFilterPresets` 覆盖内置棋盘（例如重定义 `items`），请使用不同的棋盘名。

## 验证与排错

| 现象 | 处理 |
|---|---|
| 进游戏看不到新棋盘 | 先 `/reload` 或重启；再确认 tierlist 文件名与 `itemFilterPresets` 的键完全一致 |
| 棋盘存在但里面没有目标 | tierlist 的 S/A/B/C/D 里目标太少，或目标 ID 拼写/命名空间错误；用 `/bingo filter +棋盘名` 查看实际匹配到的目标 |
| 棋盘不在列表里但文件都在 | 可能被 OP 关闭了：`/bingo carddisable list` 查看，`/bingo cardenable <棋盘名>` 恢复 |
| 目标被当成成就/物品混淆 | 用 `item!` / `advancement!` 前缀限定类型（见上文） |

## 进入游戏后选择

完成配置后，重启游戏或服务器。进入 ExBingo 的棋盘筛选列表后，可以看到 `itemFilterPresets` 中新增的棋盘名：

```text
enigmaticlegacyplus
```

选择该棋盘后，ExBingo 会按 `enigmaticlegacyplus.tierlist.json` 中的 S/A/B/C/D 分档抽取目标。
